# freeai, 무너진 무료 전제부터 다시 세워라

`freeai`의 라우팅 골격은 2026년 무료 LLM 라우터들이 모여든 설계와 같은 방향이다. 모델 단위와 플랫폼 단위 cooldown을 나누고, 첫 토큰 전에만 failover하고, 가격 0을 검사하고, 대기 시간에 상한을 둔다. 문제는 그 위에 얹힌 플랫폼 전제가 상당 부분 낡았다는 점이다. 다섯 프리셋 중 **Cerebras는 결제 수단을 등록해야 받는 $5, 30일 체험판으로 바뀌었고, Mistral 공식 문서는 Free mode에 API 접근이 없다고 밝힌다**. 그래서 `FreeAI.from_env()`가 키만 보고 두 프리셋을 켜면 체험 크레딧을 쓰거나 실제 과금이 일어난다. Groq의 무료 채팅 모델은 `openai/gpt-oss-120b`, `openai/gpt-oss-20b`, `qwen/qwen3.8-27b`로 줄었고, README 예제의 `llama-3.3-70b-versatile`은 이제 Enterprise 전용이다. 429 분류기는 신호를 엉뚱한 곳에서 찾는다. 관측된 OpenRouter 플랫폼 429는 `X-RateLimit-*` 값을 응답 본문 `error.metadata.headers`에 담았고, Gemini는 재시도 시간을 본문 `RetryInfo`에 넣는데, `_http.py`는 HTTP 헤더만 읽는다. Gemini 일일 한도는 UTC가 아니라 태평양 자정에 초기화된다. 개선 순서는 세 단계다. 먼저 분류, cooldown 창, 프리셋 데이터를 고치는 정확성 작업을 한다. 다음으로 Cloudflare Workers AI, Z.ai, Kilo, NVIDIA, Requesty 프리셋과 모델별 다중 창 한도, 영속 상태, async를 넣는다. 마지막이 OpenAI 호환 facade와 로컬 프록시, OTel이다. 이 조사는 어느 플랫폼에서도 실제 429 응답을 받아보지 못했다. 그래서 분류기를 배포하기 전에 가장 먼저 모아야 할 정보는 플랫폼별 실측 429 캡처다.

## 다섯 프리셋 중 상시 무료는 셋이고, 그마저 한도가 줄었다

OpenRouter는 여전히 기반이지만, 병목은 분당 한도가 아니라 **계정 전체가 나눠 쓰는 일일 한도**다. 공식 한도는 `:free` 변형 기준 20 RPM이고, 크레딧 구매가 10 미만이면 50 RPD, 10 이상이면 1000 RPD다 ([Limits](https://openrouter.ai/docs/api/reference/limits)). 일일 카운터는 키를 소유한 계정 단위로 UTC 자정에 초기화된다 ([Get current API key](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key)). 가격 페이지는 **실패한 시도도 일일 한도에서 차감된다**고 적고 있다 ([Pricing](https://openrouter.ai/pricing)). 계정이나 키를 늘려도 한도는 늘지 않는다. 문서 표현으로는 "we govern capacity globally"다 ([Limits](https://openrouter.ai/docs/api/reference/limits)). 20 RPM이 계정 단위인지 모델 단위인지는 공식 문서에 없다. 2025년 3월에는 계정 한도와 별개로 `limit_rpm/<model>/...` 형태의 모델별 한도(`X-RateLimit-Limit: 4`)가 관측됐다 ([LiteLLM #9035](https://github.com/BerriAI/litellm/issues/9035)). 한도 문서도 "different rate limits for different models"라는 문구를 아직 담고 있다. 그러니 계정 버킷과 모델 버킷이 겹쳐 있다고 가정하는 편이 안전하다.

OpenRouter의 라우팅 기능 중 무료 모델에 쓸모 있는 것은 생각보다 적다. 현재 카탈로그에서 **모든 `:free` 모델은 엔드포인트가 정확히 하나**다 ([Live endpoints](https://openrouter.ai/api/v1/models/google/gemma-4-31b-it:free/endpoints); [TrueFoundry](https://www.truefoundry.com/blog/openrouter-free-models-whats-actually-free-and-what-it-costs-you)). 그래서 `order`, `only`, `ignore`, `sort`, `allow_fallbacks`는 고를 대상이 없다. 쓸모 있는 것은 두 가지다. 하나는 도구나 JSON 요청에서 파라미터를 조용히 버리지 않고 지원 엔드포인트로만 보내는 `require_parameters: true`다. 다른 하나는 과금을 막는 `max_price` 0이다 ([Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)). `openrouter/free`는 요청 기능으로 걸러낸 무료 모델 중에서 **무작위로** 하나를 고른다. 혼자 쓰면 무료 모델로만 fallback하고, 실제로 답한 모델은 응답의 `model`에 나온다 ([Free Models Router](https://openrouter.ai/docs/guides/routing/routers/free-router)). 그 결과 같은 대화 안에서도 턴마다 다른 회사의 모델과 다른 데이터 정책이 걸릴 수 있다 ([TrueFoundry](https://www.truefoundry.com/blog/openrouter-free-models-whats-actually-free-and-what-it-costs-you)). Endpoints API의 `uptime_last_*`는 **rate-limit 실패를 빼고** 계산한다 ([Endpoints API](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model)). 장애 감지에는 쓸 수 있어도 429 예측에는 쓸 수 없다.

변동 폭은 SDK 설계에 직접 영향을 준다. 2026-10-05 기준 19개였던 가격 0 텍스트 모델은 2026-11-06에 13개로 줄었다. 9개가 사라지고 4개가 새로 들어왔는데, 사라진 것 중 다수는 유료 원본 모델은 그대로 두고 무료 변형만 내린 경우였다 ([Live models API](https://openrouter.ai/api/v1/models); [TrueFoundry](https://www.truefoundry.com/blog/openrouter-free-models-whats-actually-free-and-what-it-costs-you)). `expiration_date` 예고가 붙어 있던 모델은 하나뿐이었다. 개인정보 쪽은 이렇다. ZDR 목록에 든 `:free` 텍스트 모델은 `xingchen-agi/xing4.0-29b-a4b:free` 하나다 ([Live ZDR](https://openrouter.ai/api/v1/endpoints/zdr)). 계정 설정에서 "학습할 수 있는 무료 엔드포인트"를 끄면, 호스트가 하나뿐인 모델은 우회할 곳이 없어 404 `No endpoints found matching your data policy.`로 실패한다 ([Provider Logging](https://openrouter.ai/docs/guides/privacy/provider-logging); [Janitor AI](https://help.janitorai.com/en/article/openrouter-error-guide-10ear52/)). 일일 예산의 정본은 `GET /api/v1/key`의 `free_model_daily_requests{used, limit, remaining}`다. `rate_limit` 객체는 deprecated이고, `/key` 엔드포인트 자체에도 IP별 burst 제한이 있다 ([Limits](https://openrouter.ai/docs/api/reference/limits)). 공식 Python SDK `openrouter` 1.3.133은 기본적으로 5XX만 재시도하고 429 재시도나 모델 회전 기능이 없다 ([chat.py](https://github.com/OpenRouterTeam/python-sdk/blob/main/src/openrouter/chat.py)). `freeai`의 영역과 겹치지 않는다.

Groq는 상시 무료가 유지되지만 **무료 채팅 모델이 GPT-OSS 두 개와 `qwen/qwen3.8-27b`로 좁아졌다**. 세 모델은 모두 30 RPM, 1K RPD, 8K TPM, 200K TPD이고, 안전 모델 `openai/gpt-oss-safeguard-20b`는 3 RPM이다 ([Groq Rate Limits](https://console.groq.com/docs/rate-limits)). `llama-3.3-70b-versatile`, `llama-3.1-8b-instant`, `minimaxai/minimax-m2.7`은 "Enterprise"와 "ContactSales"로 표시된다 ([Groq Supported Models](https://console.groq.com/docs/models)). 문서끼리 어긋나는 곳이 하나 있다. 한도 문서는 이 수치를 "Developer plan의 기본 한도"라고 부르는데, 모델 페이지는 Developer plan 한도를 1K RPM, 250K TPM으로 적는다. 수치가 예전 무료 티어와 일치하므로 표가 무료 한도이고 문구가 오류일 가능성이 크다. 그래도 조직별 정본은 콘솔의 Limits 페이지다. 헤더는 이름과 의미가 다르다. `x-ratelimit-*-requests`는 **항상 RPD**를, `*-tokens`는 **항상 TPM**을 가리킨다. 리셋 값은 `2m59.56s` 같은 기간 문자열이고, `retry-after`는 429일 때만 붙는다 ([Groq Rate Limits](https://console.groq.com/docs/rate-limits)). 429 본문에는 `error.type`(관측값 `"tokens"`)과 "Please try again in 5.289s" 같은 문구가 들어 있다 ([Aider #3265](https://github.com/Aider-AI/aider/issues/3265)). 호환성 면에서는 `logprobs`, `logit_bias`, `top_logprobs`, `messages[].name`, `n≠1`이 400을 일으킨다 ([Groq OpenAI Compatibility](https://console.groq.com/docs/openai)). Structured Outputs는 스트리밍이나 도구와 같이 쓸 수 없다 ([Groq Structured Outputs](https://console.groq.com/docs/structured-outputs)). 추론 결과는 `message.reasoning`에 담긴다 ([Groq Reasoning](https://console.groq.com/docs/reasoning)). Groq는 기본적으로 데이터를 보존하지 않지만 남용 조사를 위해 최대 30일 로그를 남길 수 있고, 남용의 예로 **"rate-limit circumvention"**을 명시한다 ([Your Data in GroqCloud](https://console.groq.com/docs/your-data)).

Gemini API도 상시 무료가 유지되지만 Google은 **무료 수치를 문서에서 빼고 로그인해야 보이는 AI Studio 페이지로 옮겼다** ([Gemini Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)). 공식으로 확인되는 것은 한도가 **API 키가 아니라 프로젝트 단위로, 모델마다** 걸리고 RPD가 **태평양 자정**에 초기화된다는 것뿐이다. 가격 페이지 기준 무료 텍스트 모델은 `gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-3-flash-preview`, Gemma 4, 그리고 deprecated된 2.5 계열이다. `gemini-4-argon`, `gemini-3.1-pro-preview`, Omni 계열, 이미지 모델 전부는 무료 티어에 없다 ([Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)). 모델별 수치(Flash 5 RPM, 20 RPD, Flash-Lite 10 RPM, 500 RPD)는 **제3자 자료**다 ([ScriptByAI](https://www.scriptbyai.com/gemini-api-free-tier-limits/)). 그중 20 RPD만 사용자가 올린 429 본문(`quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier`, `quotaValue: 20`)으로 뒷받침된다 ([Google AI Developers Forum, 2026-09](https://discuss.ai.google.dev/t/gemini-api-free-tier-daily-quota-does-not-reset-persistent-429-resource-exhausted/183406)). 429 본문은 `RESOURCE_EXHAUSTED` 상태에 `QuotaFailure`와 `RetryInfo.retryDelay`를 담고, 메시지에 "Please retry in 40.15s"가 들어가기도 한다. `details`가 없는 짧은 형태도 있다 ([Forum, 2026-02](https://discuss.ai.google.dev/t/gemini-api-error-code-429-resource-exhausted-paid-plan/121679)). 호환 엔드포인트에서는 본문이 JSON 배열로 감싸여 온 사례가 있다 ([Forum, 2024-12](https://discuss.ai.google.dev/t/gemini-api-returns-429-issue-when-using-openai-compatible-api/52253)). `Retry-After` 헤더는 문서에 없다. 할당량의 0.03%만 쓴 상태에서도 429가 40% 비율로 나왔다는 재현 보고도 있다 ([Forum, 2026-08](https://discuss.ai.google.dev/t/429-resource-exhausted-at-0-03-of-quota-reproducible-across-projects-tiers-and-endpoints/177317)). 인증받지 않았거나 제한된 프로젝트는 403(`FREE_TIER_VERIFICATION_REQUIRED`, `PERMISSION_DENIED`)을 받고, 같은 프로젝트에서 키를 새로 만들어도 풀리지 않는다 ([Verification](https://ai.google.dev/gemini-api/docs/verification); [Troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting)). 변화도 빠르다. 2026-12-01부터 `gemini-2.5-pro`는 `gemini-3.8-flash`로, `gemini-2.5-flash`는 `gemini-3.5-flash-lite`로 자동 라우팅된다 ([Release notes](https://ai.google.dev/gemini-api/docs/changelog)). Gemini 3.6 이상과 4는 `temperature`, `top_p`, `top_k`를 무시하고, 앞으로는 400을 반환하겠다고 예고했다 ([Troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting)). 약관상 무료 사용분의 입력과 출력은 제품 개선에 쓰이고 사람 검토자가 읽을 수 있다. **EEA, 스위스, 영국의 최종 사용자에게 제공하는 서비스에는 유료 서비스만 쓸 수 있다** ([Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms)). 한국은 이용 가능 지역에 들어 있다 ([Available regions](https://ai.google.dev/gemini-api/docs/available-regions)).

나머지 두 프리셋은 더 이상 무료 프리셋이라 부를 수 없다. Cerebras는 2026-07-16부터 신규 계정에 **결제 수단을 등록해야 $5 크레딧을 주고, 이 크레딧은 30일 뒤 만료된다**. FAQ에는 "Is there a permanently free tier? No"라고 적혀 있다 ([Cerebras Rate Limits](https://inference-docs.cerebras.ai/support/rate-limits); [Change Log](https://inference-docs.cerebras.ai/support/change-log)). 요청이 들어오면 입력 토큰과 `max_completion_tokens`를 합쳐 미리 추정하고, 한도를 넘으면 처리 전에 거절한다. Shared Inference에 남은 모델은 `gpt-oss-120b`, `qwen-3.8-27b`뿐이고 `llama-3.3-70b`, `qwen-3-32b` 등은 deprecated됐다 ([Deprecations](https://inference-docs.cerebras.ai/support/deprecation)). 오류 본문은 `error` 래퍼 없이 `{"message","type","param","code"}` 형태로 평평하다 ([Live probe](https://api.cerebras.ai/v1/models)). `n`은 1만 허용되고, `gpt-oss-120b`는 `tools`와 `response_format`을 함께 보내면 거절한다 ([Cerebras OpenAI Compatibility](https://inference-docs.cerebras.ai/resources/openai)). Mistral 공식 문서는 "Free mode ... doesn't include API access"라고 쓰고, API 키를 만들려면 billing 활성화와 pay-as-you-go가 필요하다고 한다 ([Mistral Usage and limits](https://docs.mistral.ai/admin/billing-usage/usage-limits)). 2024-09-17에 생긴 무료 API 티어를 설명하던 Experiment 도움말 문서는 지금 404다 ([Help Center](https://help.mistral.ai/en/articles/455206-how-can-i-try-the-api-for-free-with-the-experiment-plan)). 다만 2026년 1월과 5월자 제3자 가이드는 아직 Experiment 플랜을 설명한다 ([unified.to](https://unified.to/blog/how_to_get_a_mistral_ai_api_key_and_connect_it_to_your_product); [fremodel](https://fremodel.pages.dev/providers/mistral-ai)). 따라서 "완전히 폐지됐다"보다 "공식 문서상 무료 API 없음, 기존 키가 동작하는지는 미확인"이 정확한 표현이다. Mistral 추론 모델은 `reasoning_effort="high"`일 때 `message.content`를 `thinking`과 `text` 청크의 리스트로 돌려준다 ([Mistral Reasoning](https://docs.mistral.ai/inference/conversations/reasoning)).

## 분류기는 OpenRouter와 Gemini가 신호를 넣는 곳을 보지 않는다

`src/freeai/`의 코드를 조사 결과와 대조해 보면, 어긋남은 라우팅 루프보다 분류기의 입력과 프리셋 데이터에 몰려 있다. 아래 표는 파일과 함수 단위로 현재 동작, 근거, 수정 방향을 정리한 것이다.

| 대상 | 현재 동작 | 조사 결과와 영향 | 수정 방향 |
|---|---|---|---|
| `providers.py` `OpenRouter._rate_limit_kind` | `metadata.provider_name`이 있으면 메시지를 보기 전에 모델 단위 `RATE_LIMIT`로 판정 | 2025년 `free-models-per-min` 계정 한도 샘플은 `provider_name: Targon`을 달고 HTTP 200으로 왔다 ([immersive-translate #2725](https://github.com/immersive-translate/immersive-translate/issues/2725)). 계정 한도를 모델 한도로 오분류해 다른 `:free` 모델을 차례로 두드리고, 시도마다 일일 한도를 쓴다 | `Rate limit exceeded: free-models-per-` 접두어를 먼저 검사. `limit_rpm/<model>`, `limit_rpd/<model>`, `metadata.raw`의 "rate-limited upstream"은 모델 단위 |
| `_http.py` `retry_delay`, `OpenRouter._rate_limit_kind`의 `_PLATFORM_LIMIT_HEADERS` | HTTP 헤더만 읽음 | 관측된 플랫폼 429 본문은 `X-RateLimit-Reset`(epoch ms, 다음 UTC 자정)을 `error.metadata.headers`에 담았다 ([pyVideoTrans #2266](https://bbs.pyvideotrans.com/show/2266)). 2026년에도 실제 HTTP 헤더가 붙는지는 미확인. 지금은 일일 한도 429에 힌트가 없어 `provider_rate_limit` 60초부터 두 배씩, 최대 900초마다 다시 시도한다 | 본문 헤더도 파싱. `free-models-per-day`는 리셋 시각까지 OpenRouter 전체 정지 |
| `_http.py` `retry_delay` | `retry-after`, `x-ratelimit-reset`, `x-ratelimit-reset-requests`만 읽음 | `retry-after-ms`를 놓친다 ([openai `_base_client.py`](https://github.com/openai/openai-python/blob/main/src/openai/_base_client.py)). Gemini는 헤더 없이 본문 `RetryInfo.retryDelay`와 메시지로만 알려준다 ([Forum](https://discuss.ai.google.dev/t/gemini-api-error-code-429-resource-exhausted-paid-plan/121679)). Gemini 429는 늘 기본값 30초부터 두 배로 늘어난다 | `retry-after-ms`, `RetryInfo`, `retry in ([\d.]+)s`, `try again in`을 차례로 파싱 |
| `_http.py` `_RESET_HEADERS`, `limits.py` `CooldownPolicy.duration` | 실패 종류와 관계없이 리셋 헤더를 힌트로 쓰고, `UNAVAILABLE`에도 힌트를 적용 | Groq는 RPD 기준 `x-ratelimit-reset-requests`를 모든 응답에 붙인다 ([Groq Rate Limits](https://console.groq.com/docs/rate-limits)). Groq 5xx가 RPD 리셋 길이만큼 쉰다 | 힌트는 429와 503에만 적용. 헤더 해석은 공급자별 dialect로 분리 |
| `limits.py` `RateLimiter` | 공급자당 RPM 하나, UTC 일 단위 RPD 하나, TPM 없음 | Groq, Gemini, Cerebras, SambaNova는 모델별로 한도를 건다. Gemini는 태평양 자정에 초기화된다 ([Gemini Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)). Groq는 8K TPM이고, Cerebras는 `max_completion_tokens`가 크면 처리 전에 429를 낸다 | 모델별 다중 창(RPM, RPD, TPM, TPD, TPH, 월), 공급자별 리셋 경계 |
| `providers.py` `_KIND_BY_STATUS[403]` | `REFUSED`, cooldown 0, 이번 요청에서만 제외 | Gemini 403 `FREE_TIER_VERIFICATION_REQUIRED`와 `PERMISSION_DENIED`는 프로젝트 전체의 실패다 ([Verification](https://ai.google.dev/gemini-api/docs/verification)). 요청마다 모든 Gemini 모델이 403을 받으며 `max_attempts`를 잡아먹는다. Mistral 403은 "subscription tier"에 없는 모델을 뜻한다 ([Mistral Error glossary](https://docs.mistral.ai/resources/error-glossary)) | 본문으로 세분화. 프로젝트 단위면 공급자 비활성, 티어 문제면 모델 영구 제외 |
| `providers.py` 404 처리, `client.py` `_record_failure` | `MODEL_GONE` 1시간 후 `invalidate()` | `No endpoints found matching your data policy`는 계정 개인정보 설정 때문에 생기는 영구 제외다. 다시 탐색하면 같은 모델이 매번 돌아온다 | `GET /api/v1/models/user`로 탐색 ([models/user](https://openrouter.ai/docs/api/api-reference/models/list-models-filtered-by-user-provider-preferences-privacy-settings-and-guardrails)). 메시지로 구분해 계정 단위 영구 제외 |
| `_http.py` `error_object` | `body.error`만 읽음(배열 래퍼는 처리) | Cerebras의 평평한 본문, Mistral의 `{"detail": ...}`와 `{"object":"error", ...}`에서 메시지가 사라지고 "HTTP 429"만 남는다 ([Cerebras live probe](https://api.cerebras.ai/v1/models); [Mistral live probe](https://api.mistral.ai/v1/models)) | 래퍼, 평평한 본문, `detail`, `detail.error`를 모두 정규화 |
| `client.py` `_MAX_BAD_REQUESTS = 2` | 공급자와 관계없이 `BAD_REQUEST` 두 번이면 요청 전체 중단 | 400을 내는 조건이 공급자마다 다르다. Groq는 `logprobs`, `name`, `n≠1` ([Groq OpenAI Compatibility](https://console.groq.com/docs/openai)), Cerebras `gpt-oss-120b`는 `tools`와 `response_format` 동시 사용, Mistral은 1을 넘는 `temperature`에서 400을 낸다. 한 공급자의 두 모델 때문에 다른 공급자가 받아줄 요청까지 끝난다 | 공급자 단위로 집계. 공급자별 파라미터 정리. 컨텍스트 초과는 더 큰 컨텍스트 후보로 이동 |
| `client.py` `_to_response`의 `EMPTY` | 내용이 비면 5초 쉬고 다른 모델로 failover | 추론 모델이 `max_tokens`를 추론에 다 쓰면 `finish_reason: "length"`로 빈 내용이 온다. OpenRouter는 이 경우 "Retrying does not help"라고 한다 ([OpenRouter Errors](https://openrouter.ai/docs/api_reference/errors-and-debugging)). Gemini 3.x는 thinking이 기본으로 켜져 있다 | 추론 예산 소진을 별도 종류로 분리. cooldown 없이 `max_tokens`나 `reasoning_effort` 조정을 안내 |
| `providers.py` `ENV_PRESETS`, `client.py` `FreeAI.from_env()` | 키가 설정된 프리셋을 모두 켬 | Mistral 키는 정의상 pay-as-you-go 키다 ([Mistral Usage and limits](https://docs.mistral.ai/admin/billing-usage/usage-limits)). Cerebras는 체험이 끝난 뒤 크레딧을 사면 과금된다. Gemini는 유료 티어로 올려도 무료 할당량이 열리지 않는다 ([Troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting)). "무료" SDK가 과금을 일으킬 수 있다 | 프리셋에 `tier`(free, trial, paid) 메타데이터 추가. `from_env()` 기본값은 free만. `mistral()`과 `cerebras()`는 명시적으로 켜야 동작 |
| `providers.py` `groq()`, README 예제 | `models`가 없으면 `/models` 전체. README는 `llama-3.3-70b-versatile` | 이 모델은 Enterprise 전용이다 ([Groq Supported Models](https://console.groq.com/docs/models)). `/models`에는 Whisper, Orpheus TTS, prompt-guard가 섞이는데, `DEFAULT_EXCLUDE`의 `*tts*`는 `canopylabs/orpheus-*`를 잡지 못한다 | 무료 모델 허용 목록 기본 탑재. README 예제를 `openai/gpt-oss-120b`로 교체 |
| `providers.py` `gemini()` | `/models` 전체 사용 | TTS와 embedding은 `*tts*`, `*embed*`로 걸러지지만, 이미지, Live, Transcribe, native-audio, Omni, `gemini-4-argon`, `gemini-3.1-pro-preview`처럼 무료가 아니거나 채팅용이 아닌 모델은 `DEFAULT_EXCLUDE`를 통과한다 ([Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)). 2026-12-01 이후 `gemini-2.5-*` ID는 다른 모델로 라우팅되고 그 모델 요금으로 과금된다고 공지됐다. 할당량까지 공유하는지는 미확인이다. README가 보내는 `temperature=0.3`은 3.6 이상에서 무시된다 | 무료 텍스트 모델 허용 목록, `models/` 접두어 제거, Gemini용 `temperature`, `top_p`, `top_k`, `n` 제거 |
| `providers.py` `Provider._require_key` | 키가 없으면 `AUTH`, 공급자를 무기한 비활성 | Kilo 익명 사용(IP당 시간 200 요청)과 OVH 익명 접근은 키 없이 무료로 쓰는 경로다 ([Kilo](https://kilo.ai/docs/gateway/models-and-providers)) | `keyless=True` 공급자 허용 |
| `providers.py` `Provider(timeout=60.0)`, `Provider.stream` | connect, read, write, pool 모두 60초. 전체 deadline 없음. 스트림 200 응답의 content-type 미검사 | httpx 계열 타임아웃은 모두 비활성 시간 기준이다 ([httpx2 timeouts](https://github.com/pydantic/httpx2/blob/main/docs/advanced/timeouts.md)). 죽은 호스트 하나에 최대 60초를 기다리고, SSE가 아닌 200 JSON 오류는 분류되지 않은 채 `EMPTY`로 떨어진다 | connect 5초, `first_token_timeout`, SDK가 강제하는 전체 deadline, content-type 검사 |

이 중 비용이 가장 큰 오류는 OpenRouter 일일 한도 처리다. 50 RPD 계정에서 `free-models-per-day` 429가 오면 현재 코드는 메시지 덕분에 플랫폼 단위로는 맞게 분류한다. 하지만 리셋 시각이 본문에 있어 힌트를 얻지 못하고, 리셋까지 몇 시간이 남았든 60초에서 900초 간격으로 계속 확인 요청을 보낸다. `free-models-per-min`이 `provider_name`과 함께 오면 사정은 더 나쁘다. 모델 단위 429로 오분류해 `max_attempts=8` 동안 다른 `:free` 모델을 차례로 시도하고, 그 실패 시도 하나하나가 일일 한도에서 빠진다 ([Pricing](https://openrouter.ai/pricing)). 50 RPD 계정에서 실패로 끝난 8회 시도는 하루 예산의 16%에 해당한다. 두 번째로 큰 문제는 `from_env()`의 과금 위험이다. OpenRouter는 가격 0 검사로 무료를 보장할 수 있다. 반면 Groq, Gemini, Cerebras, Mistral은 무료 여부가 엔드포인트가 아니라 **계정과 키의 속성**이어서 SDK가 판별할 방법이 없다. 세 번째는 `_MAX_BAD_REQUESTS`가 공급자별 호환성 차이를 "요청 자체가 잘못됐다"는 신호로 읽는다는 점이다. 공급자가 늘수록 이 판단은 더 자주 틀린다.

반대로 이미 현장 표준과 맞는 부분도 분명하다. `_is_zero_priced`는 `:free` ID라도 가격이 0이 아니면 버린다. 라우터는 맨 뒤에 둔다. stealth 모델은 `include_zero_priced`로 사용자가 직접 켜게 했는데, Crouton Alpha가 "Prompts and completions may be retained by the provider"라고 밝힌 정책과 맞는 선택이다 ([Crouton Alpha](https://openrouter.ai/stealth/crouton-alpha)). `DEFAULT_EXCLUDE`의 `*content-safety*`는 현재 목록의 `nvidia/nemotron-3.5-content-safety:free`를 걸러낸다. `error_object`는 Gemini 호환 엔드포인트의 배열 래퍼를 이미 처리하고, `_effective_status`는 200 본문 안의 `error.code`를 상태 코드로 올린다. `_content_text`는 Mistral의 리스트형 `content`에서 `text` 청크를 합친다. 모든 후보가 쉬는 중이면 `ExhaustedError.next_available_in`을 돌려주고, 스트림은 첫 출력 전에만 failover하며, `clock`과 `sleep`은 주입받는다. `py.typed`와 mypy strict도 설정돼 있다. LiteLLM과 Portkey가 사고를 겪은 뒤에 넣은 장치들이 여기에는 처음부터 들어 있다.

## Cloudflare와 Z.ai가 새 무료 기반이고, 게이트웨이는 덤이다

후보 약 25곳 중에서 OpenAI 호환 엔드포인트로 **주기적으로 초기화되는** 무료 할당을 주는 곳은 몇 안 된다. 날짜가 적힌 두 커뮤니티 목록(2026-11-02, 2026-11-05 갱신)과 각 플랫폼 공식 문서를 교차 확인한 결과는 아래와 같다 ([CYBIRD-D](https://github.com/CYBIRD-D/FREE-LLM-API-Provider); [surendranb](https://github.com/surendranb/free-inference)). 위 다섯 곳이 추가 우선순위이고, 아래 세 곳은 마지막 수단용이다.

| OVHcloud AI Endpoints | 익명 접근만 무료. IP당, 모델당 분당 2 요청 | `https://oai.endpoints.kepler.ai.cloud.ovh.net/v1` | 익명이면 카탈로그 전체 | 학습하지 않음, EU 호스팅 | 키 없는 공급자 |

Cloudflare를 1순위로 두는 이유는 다섯 가지다. 공식 문서에 상시 할당이 있고 ([Cloudflare pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)), GPU 인프라를 직접 운영해 다른 게이트웨이와 백엔드가 겹치지 않는다. "does not use Customer Content ... to train AI models"와 무보존을 공식으로 약속한다 ([Cloudflare data usage](https://developers.cloudflare.com/workers-ai/platform/data-usage/)). 오류 코드가 정밀해서 cooldown을 정확히 정할 수 있다. 같은 HTTP 429라도 **3036은 하루 무료 neuron 소진**(다음 00:00 UTC까지 정지), **3040은 용량 부족**(짧게 쉬고 회전)이다 ([Cloudflare errors](https://developers.cloudflare.com/workers-ai/platform/errors/)). 다만 지금의 `Provider`로는 그대로 담을 수 없다. base URL에 계정 ID가 들어가므로 `ENV_PRESETS`의 "환경 변수 하나에 팩토리 하나" 구조를 토큰과 계정 ID 두 변수로 넓혀야 한다. 비용 단위도 요청 수가 아니라 모델별 토큰 단가로 환산한 neuron이다. 공식 단가로는 `@cf/meta/llama-3.3-70b-instruct-fp8-fast`의 출력이 100만 토큰당 204,805 neurons로, `@cf/qwen/qwen3-30b-a3b-fp8`의 30,475보다 훨씬 비싸다 ([Cloudflare pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)). 한 커뮤니티 목록은 이를 하루 약 7.85만 토큰 대 약 52만 토큰으로 환산했다(커뮤니티 추정) ([CYBIRD-D](https://github.com/CYBIRD-D/FREE-LLM-API-Provider)). 그래서 프리셋은 작은 MoE 모델을 앞에 두고, 결제가 필요한 Kimi, GLM-5.x, DeepSeek V4 계열 8개를 빼야 한다.

Z.ai는 최신 GLM-5.3 계열이 유료인 반면, Flash 모델 세 개를 프로모션 라벨이 아닌 정식 "Free"로 가격표에 올려 두었다 ([Z.ai pricing](https://docs.z.ai/guides/overview/pricing)). 가치는 오류 코드에 있다. 모두 HTTP 429로 오지만 1302는 요청 속도 제한, 1305는 과부하, 1308은 `next_flush_time`을 담은 사용량 한도, 1113은 잔액 부족이고, 1313은 Fair Usage 위반 제한이다 ([Z.ai error codes](https://docs.z.ai/api-reference/api-code.md)). 상태 코드만 보는 분류기는 잔액 부족을 30초짜리 rate limit으로 착각한다. 2026-10-16부터 Standard API 키가 따로 관리되고 ([Z.ai key management](https://docs.z.ai/devpack/notice/api-key-management.md)), 무료 모델 동시성이 1이라는 보고는 2차 출처뿐이라 검증되지 않았다 ([ToolNavs](https://toolnavs.com/en/article/1100-zai-released-glm-47-flash-weights-and-api-free-tier-1-concurrency-and-launched-f)). 개인정보 처리방침은 학습 목적 항목에 "User Content"를 적지 않았지만, 학습하지 않는다고 명시하지도 않았다 ([Z.ai privacy](https://docs.z.ai/legal-agreement/privacy-policy.md)).

Kilo와 Requesty는 무료 모델을 기계적으로 판별할 수 있다는 점이 장점이다. Kilo `/models`는 인증 없이 `isFree`와 `mayTrainOnYourPrompts`를 내준다 ([Kilo models endpoint](https://ai-gateway.kilo.ai/api/v1/models)). Requesty는 가격 0으로 무료 모델을 걸러낼 수 있고, 하루 200 요청을 제공한다 ([Requesty pricing](https://www.requesty.ai/pricing); [Requesty models](https://router.requesty.ai/v1/models)). 그러나 두 곳의 무료 목록은 대부분 NVIDIA가 호스팅하는 Nemotron이고, 이 모델들은 OpenRouter와 NVIDIA 카탈로그에도 그대로 있다. Kilo 문서가 NVIDIA 체험 약관을 그대로 인용하는 것으로 보아 같은 백엔드로 갈 가능성이 크다 ([Kilo models & providers](https://kilo.ai/docs/gateway/models-and-providers)). 게이트웨이를 더 붙여도 실제 용량 다양성은 덜 늘고, 장애가 한꺼번에 날 위험이 있다는 뜻이다(조사 노트의 추론). NVIDIA는 Nemotron 3 Ultra, GLM-5.3-Flash, Kimi K2.6, DeepSeek V4.1 Flash까지 무료 카탈로그가 가장 넓다 ([NVIDIA models](https://integrate.api.nvidia.com/v1/models)). 반면 체험 사용이 "logged ... to improve NVIDIA products"라고 명시되고, 모더레이터가 40 RPM 한도에 "no official way to circumvent"라고 답했다 ([NVIDIA forum](https://forums.developer.nvidia.com/t/api-rate-limit-increase-is-not-granted-by-requesting-it-here/368420)). 크레딧 기반인지 순수 rate-limit 기반인지는 출처끼리 충돌해 확정하지 못했다. SambaNova는 문서에 모델별 20 RPD를 적고 있지만, 문서의 무료 모델 목록과 실제 `/models` 응답이 서로 달랐다 ([SambaNova rate limits](https://docs.sambanova.ai/docs/en/models/rate-limits); [SambaNova models](https://api.sambanova.ai/v1/models)). Cohere는 월 1,000 호출을 준다 ([Cohere rate limits](https://docs.cohere.com/docs/rate-limits)). 이 둘은 현재 `RateLimiter`로 표현할 수 없는 모델별 RPD와 월 단위 창을 요구한다.

빼야 할 곳도 분명하다. GitHub Models는 2026-07-30에 완전히 종료됐다 ([GitHub changelog](https://github.blog/changelog/2026-07-30-github-models-is-now-retired/)). Hugging Face Inference Providers는 무료 사용자 크레딧이 "None"이다 ([HF pricing](https://huggingface.co/docs/inference-providers/pricing)). Together AI는 최소 $5 구매가 필요하고 ([Together support](https://support.together.ai/articles/1862638756-changes-to-free-tier-and-billing-july-2025)), Kluster.ai는 2025-07-17에 추론 서비스를 끝냈다 ([kluster.ai](https://kluster.ai/blog/end-of-life-for-inference-fine-tuning-and-dedicated-deployments)). Chutes는 pay-as-you-go만 있고 ([Chutes pricing](https://chutes.ai/pricing)), Ollama Cloud는 2026-08-31에 가격을 개편했다 ([Ollama](https://ollama.com/blog/transparent-pricing)). 일회성 체험 크레딧만 주는 곳 중 Alibaba Model Studio는 특히 위험하다. 무료 할당이 끝나면 "Free Quota Only"를 켜지 않은 한 **자동으로 과금**되고, 재가입해도 할당을 다시 주지 않는다 ([Alibaba free quota](https://www.alibabacloud.com/help/en/model-studio/new-free-quota)). 자동 회전 SDK와 섞으면 사고가 날 구조다. Vercel AI Gateway는 무료 크레딧을 쓰는 데도 결제 수단이 필요하다(`403 customer_verification_required`) ([Vercel FAQ](https://vercel.com/docs/ai-gateway/faq)). LLM7과 Pollinations는 Claude, GPT-6.x, Grok 같은 독점 모델을 공용 프록시나 사용자 제출 경로로 노출하는데, 라이선스 근거가 확인되지 않아 회색 지대로 분류했다 ([LLM7 models](https://api.llm7.io/v1/models); [Pollinations models](https://gen.pollinations.ai/v1/models)). g4f류 리버스 엔지니어링 서비스는 기존 공개 목록도 "not legitimate"로 제외한다 ([cheahjs README, cached](https://github.com/cheahjs/free-llm-api-resources/)).

약관 면에서 정당한 패턴과 위험한 패턴은 확실히 갈린다. **여러 공급자 사이의 failover는 한도를 설계대로 쓰는 것이고, 한 공급자에서 여러 계정을 돌리는 것은 우회다.** OpenRouter는 계정이나 키를 늘려도 한도가 늘지 않는다고 하고 ([Limits](https://openrouter.ai/docs/api/reference/limits)), Groq는 rate-limit 우회를 남용 조사 사유로 든다 ([Your Data in GroqCloud](https://console.groq.com/docs/your-data)). Alibaba는 재가입으로 할당을 다시 받지 못하게 막고, Gemini는 추가 무료 프로젝트에 휴대기기 인증을 요구한다 ([Verification](https://ai.google.dev/gemini-api/docs/verification)). README와 API 설계 모두 "공급자당 계정 하나"를 전제로 해야 한다. 학습 사용 여부는 공급자마다 크게 다르다. Cloudflare와 OVH는 학습하지 않고 ([OVHcloud AI Endpoints](https://www.ovhcloud.com/en/public-cloud/ai-endpoints/)), NVIDIA와 Kilo 무료 모델과 Gemini 무료 티어는 학습하거나 사람이 검토한다. 그러니 공급자 메타데이터에 `trains_on_prompts` 플래그를 두는 것이 필요하다.

## 선행 프로젝트의 버그는 대부분 cooldown 계층에서 났다

LiteLLM Router는 재시도, cooldown, fallback 설정을 가장 많이 갖췄고, 2025년과 2026년 이슈 트래커는 cooldown 계층이 어떻게 고장 나는지 보여주는 사례집이다. 한 이슈에서는 재시도 루프가 매번 *첫* 예외의 `Retry-After`를 다시 써서, 공급자가 요구한 107초 대신 9초만 쉬었다. 허용치보다 약 12배 빠르게 두드린 셈이다 ([LiteLLM #20722](https://github.com/BerriAI/litellm/issues/20722)). 배포가 하나뿐인 그룹에서는 기본 5초 cooldown이 상류의 429 한 번을 "All deployments ... in cooldown"이라는 합성 429 연쇄로 키웠다 ([claude-lumo #130](https://github.com/jimspurgeon/claude-lumo/issues/130); [LiteLLM PR #48644](https://github.com/BerriAI/litellm/pull/48644)). 호출자가 설정한 타임아웃이 주 배포를 cooldown에 빠뜨린 사례와 ([LiteLLM #41223](https://github.com/BerriAI/litellm/issues/41223)), 스트림 중간에 난 429가 fallback 배포의 실패로 잘못 기록된 사례도 있다 ([LiteLLM #45645](https://github.com/BerriAI/litellm/issues/45645)). `freeai`는 실패마다 그 응답에서 힌트를 새로 계산하므로 첫 번째 버그는 피했다. 나머지 세 교훈은 그대로 적용된다. 마지막 후보는 실패 횟수만으로 장기 정지시키지 않는다. 실패는 정확한 (공급자, 모델, 키)에 귀속시키고, `openrouter/free`처럼 실제 모델이 응답에만 드러나는 경우에는 건강 통계를 그 모델에 쌓는다. 호출자 측 타임아웃과 400, 컨텍스트 초과는 건강 통계에서 뺀다.

게이트웨이들은 대기 상한을 명시적으로 둔다. Portkey는 요청 하나의 누적 재시도 대기를 **60초로 제한하고, `Retry-After` 하나가 60초를 넘으면 즉시 실패시킨다** ([Portkey retries](https://portkey.ai/docs/product/ai-gateway/automatic-retries)). 모든 회로가 열리면 차단기를 우회해 일단 보내는 fail-open도 쓴다 ([Portkey circuit breaker](https://portkey.ai/docs/product/ai-gateway/circuit-breaker)). LiteLLM은 "모두 cooldown 중" 429에 재시도 시각이 없어 클라이언트가 메시지를 파싱해야 했던 문제를 나중에 고쳤다 ([LiteLLM #27823](https://github.com/BerriAI/litellm/issues/27823)). `freeai`의 `max_wait=30`과 `next_available_in`은 이 둘 중 fail-fast 쪽이다. 무료 티어에서는 무작정 찔러보는 시도도 RPD를 쓰기 때문에 이쪽이 기본값으로 맞다. fail-open은 `probe_when_all_cooling` 같은 선택 옵션이면 충분하다. 반대로 고칠 점도 있다. 긴 `Retry-After`는 대개 RPD나 일일 할당량이 바닥났다는 뜻이다. 이 경우 잠들지 말고 해당 후보를 리셋 시각까지 정지시키고 넘어가야 한다는 것이 공통된 결론이다.

SDK 계층에서 가장 쓸 만한 패턴은 Pydantic AI의 response handler다. `FallbackModel`의 `fallback_on`은 예외 타입뿐 아니라 성공한 응답을 거부하는 `(ModelResponse) -> bool`도 받는다. 스트리밍 요청에는 적용하지 않고 경고만 낸다 ([Pydantic AI FallbackModel](https://pydantic.dev/docs/ai/api/models/fallback/)). 오류 분류는 rate limit, quota 소진, 과부하, 컨텍스트 초과, 인증, 모델 없음으로 나뉜다. `retry_after`는 `retry-after-ms`와 HTTP 날짜 형식까지 파싱하고, 스트림 안에서 난 오류는 `in_stream` 플래그로 구분한다 ([Pydantic AI exceptions](https://pydantic.dev/docs/ai/api/pydantic-ai/exceptions/)). 무료 모델에 흔한 "200인데 쓸모없는 응답"(잘린 JSON, 잘못된 도구 호출)을 사용자가 직접 정의할 수 있게 하려면 `freeai`에 비스트림 전용 `reject_response` 훅을 두면 된다. OpenAI Python SDK는 기본으로 429를 두 번 재시도한다 ([openai `_base_client.py`](https://github.com/openai/openai-python/blob/main/src/openai/_base_client.py)). 사용자가 OpenAI SDK를 `freeai` 프록시 앞에 두면 재시도가 곱해지므로, 문서에 `max_retries=0`을 안내해야 한다.

2025년 이후 쏟아진 무료 티어 라우터들은 기능 구성이 거의 같아졌다. `fast`, `smart`, `long-context` 같은 가상 별칭, 분 단위, 일 단위, 소멸 모델을 나눈 cooldown, 사라진 모델에 붙이는 TTL, 재시작 후에도 남는 상태, 응답 헤더로 노출하는 실제 서빙 모델, 유료 차단이 그것이다. waseemnasir2k26/free-llm-router는 "There is deliberately no `--paid-ok` flag"라는 원칙을 두고, 모든 한도 항목에 `source` URL과 `last_verified` 날짜를 붙인다 ([free-llm-router](https://github.com/waseemnasir2k26/free-llm-router)). freellmapi-extended는 매일 상류 카탈로그를 비교해 사라진 모델을 사용자보다 먼저 찾는다 ([freellmapi-extended](https://github.com/SeyhmusKaya/freellmapi-extended)). tokkkie와 FreeRideV3는 새로 발견한 모델의 도구 호출을 실제로 시험해 본다 ([tokkkie](https://github.com/tokkkie/free-model-router); [FreeRideV3](https://github.com/Shaivpidadi/FreeRideV3)). freellm은 다른 모델로 몰래 바꾸는 것을 거부하는 strict mode를 둔다 ([freellm](https://github.com/devansh-365/freellm)). 도구 호출 검증이 필요한 이유는 OpenRouter의 Exacto 발표에도 나온다. 도구 사용 정확도는 같은 모델이라도 공급자마다 벤치마크가 시사하는 것보다 크게 다르다 ([Exacto](https://openrouter.ai/blog/announcements/provider-variance-introducing-exacto/)). 눈여겨볼 점은 이 프로젝트들이 거의 모두 **프록시 서버**라는 것이다. 프로세스 안에서 동작하는 라이브러리에 선택형 프록시를 붙이는 방식은 경쟁이 적다.

품질 순위에는 학습형 라우터보다 가벼운 신호가 맞다. RouteLLM은 강한 모델과 약한 모델이 고정된 쌍을 전제로 학습된다 ([RouteLLM](https://github.com/lm-sys/RouteLLM/)). 무료 모델이 목록에 머무는 기간은 중앙값 75일에 불과하다 ([TrueFoundry](https://www.truefoundry.com/blog/openrouter-free-models-whats-actually-free-and-what-it-costs-you)). 대안은 두 가지다. Artificial Analysis API는 하루 1,000 요청 안에서 지능, 코딩 지수와 속도를 주지만, 출처 표기와 캐시를 요구하고 클라이언트 코드에 넣지 말라고 한다 ([Artificial Analysis API](https://artificialanalysis.ai/documentation)). OpenRouter 모델 목록의 `benchmarks.artificial_analysis`는 같은 지수를 무료로 주지만, 무료 모델 중 상당수는 이 값이 비어 있다 ([Models API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)). 사용자 정의 별칭과 `prefer` 패턴을 기본으로 두고, 점수는 선택형 보강으로만 쓰는 편이 비용 대비 낫다.

## 다음 병목은 동결된 httpx와 요청 수만 세는 제한기다

가장 먼저 내려야 할 공학적 결정은 HTTP 스택이다. `httpx` 0.28.1은 2024-12-06 이후 안정 릴리스가 없고 그 뒤로는 `1.0.devN` 사전 릴리스뿐이다 ([httpx PyPI](https://pypi.org/pypi/httpx/json)). Pydantic이 관리하는 포크 `httpx2`는 2.16.0(2026-10-21)까지 나왔고, `openai-python`과 `anthropic-sdk-python`이 이미 이쪽으로 옮겼다 ([httpx2](https://github.com/pydantic/httpx2); [openai pyproject](https://github.com/openai/openai-python/blob/main/pyproject.toml)). httpx2는 공개 API가 같아 `MockTransport` 테스트가 그대로 돌고, 두 패키지를 한 환경에 함께 설치할 수도 있다 ([httpx2 migration](https://github.com/pydantic/httpx2/blob/main/docs/migration.md)). 2.5.0에서 SSE 지원(`client.sse()`)이 들어왔고, 2.10.0에서 이벤트당 기본 1 MiB 상한(`max_event_size`)이 추가됐다 ([httpx2 SSE](https://github.com/pydantic/httpx2/blob/main/docs/sse.md); [httpx2 CHANGELOG](https://github.com/pydantic/httpx2/blob/main/src/httpx2/CHANGELOG.md)). 다만 httpx2는 2.15.0에서 Python 3.10 지원을 끊었다 ([httpx2 CHANGELOG](https://github.com/pydantic/httpx2/blob/main/src/httpx2/CHANGELOG.md)). `requires-python >= 3.12`인 `freeai`에는 문제가 없다. 지금 할 일은 `_http.py`를 진짜 경계로 만드는 것이다. 현재는 `providers.py`가 `httpx`를 직접 import하므로 HTTP 의존을 `_http.py` 한 곳에 모아야 한다. 그러면 나중에 httpx2로 옮기는 일은 import 이름 하나를 바꾸는 수준이 된다. respx와 pytest-httpx는 classic `httpx`에 묶여 있으니 테스트 도구로 들이지 않는다 ([respx](https://pypi.org/project/respx/); [pytest-httpx](https://pypi.org/project/pytest-httpx/)).

제한기는 요청 수 하나만 세는 구조에서 **가중치가 있는 다중 창**으로 바뀌어야 한다. 현재 `RateLimiter`는 요청마다 타임스탬프를 하나씩 `deque`에 쌓는 sliding log다. 이 방식은 RPM에는 정확하지만 TPM이나 neuron처럼 가중치가 붙는 비용은 표현하지 못한다. GCRA나 token bucket은 키 하나당 숫자 몇 개로 일정한 메모리만 쓰면서 가중치를 지원하고, 다음 허용 시각을 정확히 알려준다. 반면 고정 창은 자정 같은 경계에서 리셋되는 상류 할당량을 흉내 낼 때 쓰라고 권장된다 ([PyrateLimiter](https://github.com/vutran1710/PyrateLimiter)). 그러니 RPM과 TPM은 GCRA로, RPD는 공급자별 경계(UTC, America/Los_Angeles, 월)를 가진 고정 창으로 나누면 된다. 토큰은 요청 전에 문자 수를 4로 나눈 값에 `max_tokens`를 더해 예약하고, 응답의 `usage`로 정산한다. OpenAI도 한도를 "max_tokens와 문자 수 기반 추정치 중 큰 값"으로 계산한다 ([OpenAI rate limits](https://developers.openai.com/api/docs/guides/rate-limits)). 응답 헤더가 주는 한도와 남은 양은 로컬 추정치를 덮어쓰는 정답으로 다룬다. 무료 한도는 자주 바뀌기 때문이다.

재시도와 cooldown은 두 층의 예산과 반개방 확인으로 정리된다. failover SDK에서 "재시도"는 대부분 지연 없이 다음 후보로 넘어가는 일이다. 같은 엔드포인트를 다시 칠 때만 full jitter(`uniform(0, min(cap, base*2**n))`)를 쓴다 ([AWS backoff simulator](https://github.com/aws-samples/aws-arch-backoff-simulator/blob/master/src/backoff_simulator.py)). 요청별 `max_attempts`에 더해 프로세스 단위 재시도 토큰 버킷이 필요하다. gRPC는 `maxTokens` 10, `tokenRatio` 0.1을 쓰고, 토큰이 절반 아래로 떨어지면 재시도를 막는다 ([gRPC A6](https://github.com/grpc/proposal/blob/master/A6-client-retries.md)). Google SRE는 재시도를 요청의 10% 이하로 묶으면 과부하 시 부하 증폭이 약 3배에서 1.1배로 준다고 설명한다 ([SRE book](https://sre.google/sre-book/handling-overload/)). 이 버킷이 있으면 OpenRouter처럼 공용 상류가 죽었을 때 모든 스크립트가 모든 무료 엔드포인트를 훑는 사태를 막을 수 있다. cooldown은 Envoy처럼 연속 퇴출 횟수에 비례해 늘리고, 상한과 감쇠를 둔다 ([Envoy outlier detection](https://www.envoyproxy.io/docs/envoy/latest/intro/arch_overview/upstream/outlier)). cooldown이 끝나면 한 번에 하나의 요청만 보내 확인하는 반개방 상태를 두는 것으로 충분하다. hedging은 맞지 않는다. 실패한 요청도 분당 한도에 포함되기 때문이다 ([OpenAI rate limits](https://developers.openai.com/api/docs/guides/rate-limits)). 건강 순위는 성공률과 TTFT의 EWMA를 power-of-two-choices로 고르는 방식이 쏠림 없이 부하를 나눈다 ([Finagle](https://twitter.github.io/finagle/guide/Clients.html)).

async와 영속 상태는 sans-I/O 코어 하나로 함께 풀린다. OpenAI와 Anthropic SDK는 코드 생성기로 sync와 async 클래스 계층을 따로 찍어낸다. 손으로 유지하는 작은 라이브러리에는 순수 함수로 된 코어(후보 계획, 결과 반영, 제한기 계산, SSE 파싱, 응답 정규화)에 얇은 I/O 껍데기 두 개를 씌우는 편이 중복이 가장 적다. httpcore처럼 async 코드에서 sync 코드를 정규식으로 생성하는 방법도 있다 ([httpcore unasync.py](https://github.com/encode/httpcore/blob/master/scripts/unasync.py)). 잠금은 지금처럼 `threading.Lock` 하나로 유지하되, 잠금 안에서 `await`이나 I/O를 하면 안 된다. `asyncio.Lock`은 스레드 안전하지 않다 ([asyncio sync](https://docs.python.org/3/library/asyncio-sync.html)). `freeai`가 이미 잠금 밖에서 `sleep`하는 것은 맞는 설계다. 상태 저장소는 memory, SQLite(WAL), 선택형 Redis 세 단계로 둔다. SQLite WAL은 같은 호스트의 로컬 디스크에서만 동작한다 ([SQLite WAL](https://www.sqlite.org/wal.html)). 공유 상태에서는 `time.monotonic` 대신 epoch 벽시계를 써야 한다. 모노토닉 시계는 프로세스마다 다르기 때문이다 ([PyrateLimiter](https://github.com/vutran1710/PyrateLimiter)). 공유할 대상은 계정 단위 사실인 cooldown과 할당량 카운터다. 잡음이 많은 건강 EWMA는 프로세스 안에 둬도 된다.

스트리밍과 관측성은 작은 수정이 여럿 쌓인 영역이다. 현재 `iter_sse`는 `data:` 줄만 읽고 `event:` 필드와 여러 줄 `data`를 무시한다. WHATWG 명세는 CR, LF, CRLF 줄끝, 주석 줄, 여러 줄 `data`를 `\n`으로 잇는 규칙, 빈 버퍼일 때 이벤트를 보내지 않는 규칙을 정해 두었다 ([WHATWG SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html)). httpx 타임아웃은 모두 비활성 시간 기준이라 전체 deadline은 SDK가 직접 계산해 시도마다 남은 시간을 넘겨야 한다 ([httpx2 timeouts](https://github.com/pydantic/httpx2/blob/main/docs/advanced/timeouts.md)). 대기열이 긴 무료 엔드포인트에는 별도의 `first_token_timeout`이 특히 효과적이다. 로깅 면에서는 `logging.getLogger("freeai")`에 `NullHandler`가 붙어 있지 않아, 로깅을 설정하지 않은 앱에서는 `logger.warning`이 stderr로 새어 나간다. Python 문서는 라이브러리에 `NullHandler`만 붙이라고 권한다 ([Logging HOWTO](https://docs.python.org/3/howto/logging.html#configuring-logging-for-a-library)). OTel GenAI 규약은 별도 저장소(`semantic-conventions-genai`)로 옮겨 갔고 여전히 Development 상태다. 2026년에도 메트릭 이름이 바뀌었다 ([semantic-conventions-genai](https://github.com/open-telemetry/semantic-conventions-genai); [client-inference](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)). 그래서 안정 계약은 `on_attempt` 같은 의존성 없는 훅으로 두고, OTel 매핑은 `freeai[otel]` extra에 실험적 기능으로 격리하는 것이 맞다. 같은 문서는 TTFT의 "chunk"를 "new, non-empty output"을 담은 이벤트로 정의하는데, 이 정의를 그대로 failover 경계로 쓰면 된다. 패키징은 사소하지만 바로 고칠 수 있다. `pyproject.toml`은 `uv_build>=0.9.28,<0.10.0`을 쓰는데 현재 문서 권장은 `>=0.13.7,<0.14`이고 ([uv build backend](https://docs.astral.sh/uv/concepts/build-backend/)), PEP 639 `license` 필드와 라이선스 파일이 없다 ([Writing pyproject.toml](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/)). 배포는 Trusted Publishing을 쓰고 `pypa/gh-action-pypi-publish`로 attestation을 생성하는 경로가 표준이다 ([gh-action-pypi-publish](https://github.com/pypa/gh-action-pypi-publish)).

## 결론

이번 조사로 `freeai`가 실제로 하는 일의 정의가 바뀌었다. 처음 설계는 "429가 나면 다른 무료 모델로 넘어가는 재시도 루프"였지만, 2026년의 무료 생태계에서 이 SDK는 **할당량 회계 스케줄러**에 가깝다. 실패한 시도도 일일 한도에서 빠지고, 한도는 공급자마다 다른 창(분, 시간, 일, 월, neuron)과 리셋 경계(UTC, 태평양 시간, 기간 문자열)로 걸린다. 같은 429 상태 코드가 "1초 쉬라"와 "오늘은 끝났다"와 "잔액이 없다"를 모두 뜻한다. 그러니 새 공급자를 하나 더 붙이는 것보다 신호를 정확히 읽는 것의 가치가 더 크고, P0 아홉 건이 기능 추가보다 앞선다. 또 무료 여부가 엔드포인트가 아니라 계정의 속성인 공급자가 대부분이라, 가격으로 무료를 증명할 수 있는 곳은 OpenRouter와 일부 게이트웨이뿐이다. 나머지는 사용자 선언과 허용 목록에 기댈 수밖에 없고, README는 이 보장이 더 약하다는 사실을 숨기지 말아야 한다.

두 번째 함의는 데이터를 다루는 방식이다. 한 달 사이 OpenRouter 무료 모델 9개가 사라졌고, Cerebras와 Mistral은 반년도 안 돼 무료 프리셋에서 빠졌으며, Gemini는 수치를 문서에서 내렸다. 한도와 모델 목록을 코드 상수로 두면 SDK는 배포하는 순간부터 낡기 시작한다. 한도 항목마다 `source`와 `last_verified`를 달고, 응답 헤더로 스스로 고치고, 실측 계약 테스트로 정기적으로 다시 확인하는 구조여야 한다. 무료 풀은 줄어들 뿐 아니라 서로 겹친다. 여러 게이트웨이가 같은 Nemotron 백엔드로 이어지기 때문이다. 그래서 공급자 개수보다 Cloudflare, Z.ai, Groq, Gemini처럼 인프라가 실제로 다른 곳을 섞는 것이 가용성을 높인다.
